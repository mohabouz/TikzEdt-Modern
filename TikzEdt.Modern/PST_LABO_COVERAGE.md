# PST-Labo coverage

The schema was checked against the 39 `define@key` entries in the official
PST-Labo 2.08 sources, including OpenTap in pst-laboObj.tex. Compilation coverage
uses the installed 2.07 package and LuaPSTricks. Each native key has a tested
generated-source variant; that does not imply every possible combination is useful.

## Native properties

| Area | Keys |
| --- | --- |
| Vessel | glassType, tubePenche, bouchon, pince |
| Labels | etiquette, Numero |
| Liquids | niveauLiquide1/2/3, aspectLiquide1/2/3 |
| Attachments | tubeDroit, tubeCoude, tubeCoudeU, tubeCoudeUB, tubeRecourbe, tubeRecourbeCourt, doubletube, refrigerantBoulles, tubeDegagementDroit |
| Heating/gas | barbotage, recuperationGaz, tubeSeul, becBunsen |
| Contents | substance, solide |
| Titration | burette, phmetre, agitateurMagnetique, niveauReactifBurette, couleurReactifBurette, reactifBurette, reactifBecher |
| Pipette | niveauReactif, couleurReactif |
| Distillation | AspectMelange, CouleurDistillat |
| Separation | OpenTap |

Custom RGB liquid colours and common linewidth/linecolor/fillcolor controls are
editor additions. Contents accept the package's supported material macros with
optional counts (0-80) and required named colours. Labels accept balanced TeX
text/math; the visual field rejects file/process-related commands. This is not
a TeX security sandbox; ordinary source compilation retains normal TeX behaviour.

Separating-funnel colours require local AqueoPhase and OrganicPhase style
overrides because the package's drawing does not consult aspectLiquide1/2.
These styles are grouped per object to prevent changes leaking to other vessels.
Generic vessels draw their layers in package order; choose nested fill levels
(layer 3 <= layer 2 <= layer 1). Separation instead uses two phase boundaries
on its 0-16 coordinate scale, with the upper boundary above the lower boundary.

## Graphics, frames and connections

An isolated temporary capture frame is only a compiler implementation detail.
Transparent geometry is excluded when measuring ink; the frozen vector drawing
is cropped without rasterization. Metadata retains the capture-to-ink offset,
so TeX assembly and canvas positions agree. Scene export uses visible bounds.

Connecting tubes are generated by the editor using PSTricks paths, not a new
PST-Labo package key. Straight/rounded orthogonal/cubic routes share the same
path construction for WPF and TeX. Endpoint attachments use stable apparatus IDs;
deletion cleans dependent connections and duplication remaps internal IDs.
Endpoints can attach to generic cardinal bounds or a user-picked local point.
These are drawing relationships, not dimensioned physical connectors, automatic
hose routing, flow simulation or laboratory safety validation.

## Explicit limitations

- `pstBigPipette` is incomplete in inspected 2.07/2.08 sources: an undefined clip
  helper and an arc without required angle arguments prevent compilation. The
  standard pipette is usable; no replacement drawing is silently substituted.
- `tubeDegagementDroit` is defined but not used by package drawing code. The
  advanced panel identifies this rather than promising a visible effect.
- Some keys are ignored by particular apparatus or are mutually exclusive;
  relevant controls are filtered and attachment alternatives switch atomically.
- There is no promise that every private helper is a standalone drawing.
- Arbitrary PSTricks programs, custom user macros/styles and deformed apparatus
  are not round-trip visually editable. Manually changed generated TeX is preserved
  and visual import refuses to overwrite it.
- LuaLaTeX is tested. The prior full XeLaTeX assembly test timed out on this host;
  direct pdfLaTeX rendering of PSTricks is not supported.
